# call me maybe

## Description

**call me maybe** turns natural-language requests into function calls.
Given *"What is the sum of 2 and 3?"* and a list of functions, the program
does not answer `5`, it writes:

```json
{"prompt": "What is the sum of 2 and 3?", "name": "fn_add_numbers", "parameters": {"a": 2.0, "b": 3.0}}
```

It uses the small model **Qwen/Qwen3-0.6B** with **constrained decoding**:
at each step, the tokens that would break the JSON or the function schema
are removed, so the output is always valid. The model still decides which
function to call and what the argument values are.

## Instructions

Requirements: Python ≥ 3.10 and [uv](https://docs.astral.sh/uv/).

```bash
make install      # uv sync
make run          # uv run python -m src
make debug        # run with pdb
make lint         # flake8 + mypy (required flags)
make lint-strict  # flake8 + mypy --strict
make clean        # remove caches
```

The first run downloads the model (~1.2 GB).

### Example usage

```bash
uv run python -m src
uv run python -m src \
    --functions_definition data/input/functions_definition.json \
    --input data/input/function_calling_tests.json \
    --output data/output/function_calling_results.json
```

Defaults: input files in `data/input/`, output in
`data/output/function_calling_results.json` (the folder is created).

## Algorithm explanation

### Files

| File | Role |
|---|---|
| `src/__main__.py` | options, main loop, error messages |
| `src/io_utils.py` | read and validate input files, write the output |
| `src/models.py` | pydantic models |
| `src/vocabulary.py` | token id → text, from `vocab.json` |
| `src/prompt.py` | text given to the model |
| `src/decoder.py` | constrained decoding |

### 1. Vocabulary

`get_path_to_vocab_file()` gives `vocab.json` (token → id). Qwen uses
byte-level BPE: each byte is written as a printable character (`Ġ` = space,
`Ċ` = newline). `vocabulary.py` reverses this to get the real text of each
token, so we know what each token would add to the output.

### 2. The structure is forced, the values are generated

We never let the model write the JSON skeleton. We encode it and append it
to the context ourselves. Parts in quotes are forced, the others are
generated by the model under constraints:

```
<prompt> '{"name": "' NAME '", "parameters": {"a": ' NUMBER ', "b": ' NUMBER '}}'
```

### 3. One generation step (`ConstrainedDecoder.pick`)

1. `get_logits_from_input_ids(context)` gives one score per token;
2. we build the list of **allowed** tokens;
3. every other score is set to `-inf`;
4. we take the best remaining token (argmax).

### 4. Allowed tokens

| Value | Rule |
|---|---|
| function name | (text so far + token) must be the start of one of the names. When only one name is left, it is completed without calling the model. A `"` is added at the end of each name so that `fn_add` is not a prefix of `fn_add_numbers`. |
| `number` | tokens made of `0-9 . -` such that (text so far + token) matches `-?(\d+(\.\d*)?)?`. When the number is complete, tokens starting with `,` or `}` are also allowed: choosing one means "finished". |
| `integer` | same with `-?\d*`. |
| `boolean` | choice between `true` and `false` (same as the name). |
| `string` | any token without `\` or control characters. The first token containing `"` ends the string (only the part before the quote is kept). |
| `enum` | choice between the listed values (same as the name). |

The values are stored in a pydantic `FunctionCall` and the file is written
with `json.dump`, so the output is always valid JSON.

## Design decisions

- **Forced skeleton**: the structure cannot be wrong and costs no model call.
- **Greedy (argmax)**: same result on every run.
- **Vocabulary sorted once** at start-up (string / number / end-of-number
  tokens), so each step only filters small lists.
- **No backslash in strings**: no JSON escapes to manage; the model writes
  e.g. `[0-9]+` instead of `\d+`.
- **Empty `<think></think>`**: turns off Qwen3's reasoning mode.
- **Unknown types** are generated as strings.
- **Limits**: 50 tokens per string, 20 characters per number.
- **Errors**: every file problem raises a `ValueError` with a clear message,
  printed by `main`; a failing prompt is reported and skipped.

## Performance analysis

- **Validity**: 100 % by construction: every token is checked, and the
  file is written by `json.dump` from validated data.
- **Accuracy**: the function and values are chosen by the model inside the
  constraints. Clear prompts are handled well; ambiguous prompts are the
  main source of errors.
- **Speed**: one model call per generated token only; the example set runs
  well under 5 minutes on CPU.

## Challenges faced

- **A token is not a character**: one token can hold several digits, or a
  word and a quote. Every check is done on (text so far + token text).
- **Byte-level vocabulary**: `vocab.json` is not plain text; the GPT-2 byte
  table is rebuilt to read it.
- **Knowing when a number ends**: solved by allowing `,` / `}` tokens once
  the number is complete.
- **Names that are prefixes of other names**: solved with the closing quote.

## Testing strategy

- Fake model (same methods as the SDK, small vocabulary) to check that the
  decoder returns exactly what the model "wants", and that with random
  logits the output always matches the schema.
- Error cases: missing file, invalid JSON, wrong structure, invalid types,
  unknown option.
- Real runs on `data/input/`, checking the output file with `json.load`.
- `make lint` and `make lint-strict`.
